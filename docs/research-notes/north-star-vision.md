**North star (stated 2026-07-18):** Build a bottom-up NBA **matchup simulator**. For each player, attach as many stats/splits as possible (base stats + fine-grained splits like perimeter defense at home, shooting vs taller/shorter defenders, contested/uncontested, by zone). Then, matching two teams, project each player's and the team's stats via opponent-adjusted matchup analysis. Eventually surfaced on a website (dashboards, shot charts, daily predictions). See [[modeling-architecture]] for the layered pipeline.

**CAPSTONE END GOAL (user, 2026-07-18): a full possession-level GAME SIMULATOR.** Monte-Carlo a whole game (~200 possessions × many sims) → win prob + score + every player's stat line with uncertainty. Components: (1) rotation engine = predicts on-court 5 per team over time (minutes projection + substitution patterns + coach tendencies + foul trouble/garbage time) — this is the PREDICTION-side lineup model (distinct from historical reconstruction/solver A which is deterministic and used to TRAIN it); (2) assignment model (who guards whom); (3) possession engine (pace → usage → outcome via xPTS × shooter skill vs defender quality/pressure → rebound/foul/TO → update state). EVERY prior component is an input: player projections, xPTS shot model, defender quality + defensive pressure, RAPM, matchup data, rotation model, Elo anchor. Honest hard parts: compounding per-possession error, aggregate calibration (usage→100%, realistic pace/totals), rotation realism (hardest), correlated outcomes (naive independent-possession under-disperses). Strategy: build shared ingredients; do a DISTRIBUTIONAL sim first (project player stat-line distributions + correlations, sample — robust, reuses projection/matchup work), then the full possession sim, and BAKE-OFF which predicts better. Immediate keystone unchanged: solver A (historical stint reconstruction) trains RAPM + rotation + possession models.

**Data mapping:**
- HAVE (Layer 2): base stats, home/away splits, contested/rim tracking, shot coords from pbp.
- NEED TO SCRAPE (endpoints exist, fit our pattern): `leaguedashptdefend` + `playerdashptshotdefend` (perimeter defense), `leaguedashplayerptshot`/`playerdashptshots` (shooting vs tight/open defender, shot clock, dribbles), `boxscorematchupsv3`/`leagueseasonmatchups` (who guarded whom), `commonplayerinfo`/`playerprofilev2` (heights/weights/positions — needed for taller/shorter), `boxscorehustlev2` (contested/deflections), `shotchartdetail` (official zones, already planned).

**Two honest constraints:**
1. Coverage: matchup data starts ~2017-18 (verify), hustle ~2015-16; per-shot defender identity+height is NOT available (withdrawn after SportVU era). So "FG% vs taller/shorter defenders" must be built from MATCHUP-AGGREGATES (2017-18+) × heights, not per-shot, not back to 2013-14. Base/shooting go back to 2013-14. **DECISION (user, 2026-07-18): 2017-18+ coverage for matchup/defensive endpoints is fine — just pull that range for those; keep base/pbp/shooting full-range 2013-14+.**
2. Small-sample noise is the make-or-break: thin splits (e.g. perimeter D, at home, vs taller) have tiny samples → overfit/mispredict. MUST use hierarchical / empirical-Bayes shrinkage toward player overall rate + league priors. Bake in from the start.

**Modeling shape:** opponent-adjusted player-stat projection = player baseline × opponent defensive profile × pace/role, regularized. Team totals aggregate up from player projections.

**Offseason / preseason projection = the model's center (user, 2026-07-18).** Current Elo is roster-blind (just regresses last year 25% to mean) — a real weakness for early-season/roster-change predictions. Fix = bottom-up preseason ratings: preseason team rating = Σ(projected player value × projected minutes) for the NEW roster; a player's value travels with him on trades. BUILT SO FAR (age-independent, no API): `player_seasons.parquet` (per-player-season substrate, value metric v1 = minutes-weighted PIE) via scripts/22; Marcel-style projection engine + leakage-free backtest via scripts/23 — beats naive baselines on PIE/PTS/REB/AST (PIE corr 0.795 vs 0.731, 9.2% lower error). STILL NEEDED (blocked on scraping, do after box-score run): aging curves (need birthdates via `commonplayerinfo` — biggest remaining lift; engine is currently age-blind), rookie priors (draft-slot via `drafthistory`), minutes projection, roster aggregation (`commonteamroster`). Then blend preseason prior with in-season via higher early Elo K / decaying weight, and widen uncertainty early. Swap PIE → WAR as the value metric once WAR is built. Backtest the whole offseason method like the WAR bake-off.

**Also wanted: a basketball WAR metric (user, 2026-07-18).** Framework = impact/100 (opponent/teammate-adjusted) → above replacement (~-2 pts/100) → wins (~30 pts/win). Grounded in existing metrics (VORP, RAPTOR WAR, EPM/LEBRON Wins, PIPM). Two tiers: (1) box+tracking WAR buildable now from player_games (BPM/VORP-style, full 13 seasons); (2) RAPM-blended WAR = ridge regression on pbp STINTS blended with box prior — the in-depth version. Tier 2 needs lineup/stint reconstruction from pbp (period-start lineups = the hard part) — SAME infra the matchup engine needs, so build stints once. Caveats: RAPM noisy single-season (use multi-year/box prior), replacement & pts/win are calibrated conventions, defensive attribution uncertain.

**WAR framework bake-off (user, 2026-07-18):** don't pick one WAR framework by taste — backtest several and pick empirically. KEY: WAR has no ground truth, so evaluate via a downstream observable target. Judge (priority order): (1) out-of-sample game/team-win prediction via the EXISTING walk-forward + calibration harness (log-loss/Brier/win-MAE) — PRIMARY; (2) roster-change/on-off validation; (3) year-to-year stability; (4) retrodiction of team wins (secondary, partly circular). Bake-off frameworks: Win Shares, BPM→VORP, pure RAPM, blended RAPM+box prior, tracking-enhanced. Hold replacement level + pts/win CONSTANT across frameworks so only the impact-estimation core is compared. "Best" is objective-dependent (retrodictive ≠ predictive); pick PREDICTIVE as primary given matchup-engine + betting goals, but report both.
